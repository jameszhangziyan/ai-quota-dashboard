数据说明

数据读自这台 Mac 上各工具的本地日志：Claude Code（~/.claude）、Codex（~/.codex）、Kimi Work（Kimi 桌面版内置日志）、WorkBuddy（~/.workbuddy/traces）、Gemini CLI（~/.gemini）。

Kimi 普通聊天、ChatGPT 网页版和桌面聊天不会在本地记录 token，所以无法统计；Kimi Work 的 Agent 任务可以统计。WorkBuddy 里调用 Kimi 模型的用量也会算进「按模型厂商」的 Kimi。

合计 = 输入 + 缓存写入 + 缓存读取 + 输出。缓存读取一般按很低的价格计费，所以 token 数大不等于花费高。

上方额度百分比都是官方数据，包含所有设备的用量；每块从圆心向外填充的长度就是使用率。Kimi 的会员额度是 Kimi Work 和 Kimi Code 的合计，小字显示其中 Code 占多少。每块里的「本月消耗 N 万 token」= 输入 + 缓存写入 + 输出，不计缓存读取（每轮对话都会重读整段上下文，计入会放大几十倍）：Claude、ChatGPT、Kimi Work、Gemini 取这台 Mac 本地日志里本月 1 日以来的 token 数（Gemini 只统计 Gemini CLI，没有就显示「—」），其他设备的用量不在其中，所以会偏低；WorkBuddy 无法按自然月拆分，用的是账号本计费周期（约一个月，到下次重置为止）已用积分 × 这台 Mac 实测的每积分 token 数。Claude、ChatGPT、Gemini 的大号百分比是 5 小时额度，小字是本周额度。颜色：平时用各账号的品牌色，≥70% 变黄，≥90% 变红。

WorkBuddy、Kimi、Gemini 的账号额度需要在 额度登录设置 里粘贴一次登录请求（只能在 Mac 本机打开）。
